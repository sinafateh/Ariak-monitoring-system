# صفحه مدیریت کاربران — ماکت HTML/CSS/JavaScript

این بسته یک پیش‌نمایش تعاملی مستقل برای فلو مدیریت کاربران سامانه مانیتورینگ اعلام حریق است. بدون فریم‌ورک یا وابستگی build اجرا می‌شود.

## اجرا

1. فایل `index.html` را در مرورگر باز کنید؛ یا بهتر است پوشه را با یک static server محلی اجرا کنید.
2. از منوی سمت راست/کناری وارد «مدیریت کاربران» شوید.
3. با «جزئیات» وارد صفحه کاربر شوید؛ چهار تب اطلاعات، پروژه‌ها و پنل‌ها، مجوزها و سوابق فعالیت وجود دارند.
4. با «مدیریت دسترسی» پروژه‌ها، پنل‌ها و اختیارات مدیریتی را تغییر دهید، سپس «بازبینی تغییرات» را باز کنید.
5. می‌توانید کاربر نمونه بسازید، اطلاعات حساب نمونه را ویرایش کنید، وضعیت حساب را تغییر دهید و گزارش فعالیت نمونه را به CSV دریافت کنید.

## فایل‌ها

- `index.html`: ساختار صفحه و shell رابط کاربری
- `styles.css`: استایل RTL، واکنش‌گرا، تم روشن و پشتیبانی پایه از تم تیره سیستم
- `app.js`: داده نمونه، رندر صفحات، تعاملات، فرم‌ها و فلو بازبینی دسترسی

## نکته مهم درباره اتصال به پروژه اصلی

این ماکت به سرور و PostgreSQL متصل نیست. داده‌ها در متغیرهای JavaScript نگهداری می‌شوند و با refresh صفحه بازنشانی می‌شوند. نام کاربری و رمز نمونه هرگز برای احراز هویت واقعی استفاده نمی‌شوند و رمز اولیه فرم ایجاد کاربر نگهداری نمی‌شود.

برای ادغام در پروژه واقعی با ساختار Vanilla JS موجود:

1. قرارداد APIهای واقعی احراز هویت، کاربران، پروژه‌ها، پنل‌ها، مجوزها و audit log را در `server/index.js` بررسی کنید.
2. داده‌های ثابت `users`, `projects`, `profiles` و `activities` را با درخواست‌های authenticated به API واقعی جایگزین کنید.
3. توابع `openUserForm`, `saveAccess`, `toggleUserStatus` و `renderActivity` را به عملیات واقعی API متصل کنید؛ تأیید رابط کاربری به‌تنهایی ذخیره محسوب نمی‌شود.
4. endpointهای سمت سرور باید مجوز actor و محدوده دسترسی به پروژه/پنل را برای هر درخواست اعتبارسنجی کنند.
5. چون `src/main.js` پروژه اصلی از توابع render و handlerهای مشترک استفاده می‌کند، صفحه را با قرارداد routing/state فعلی پروژه یکپارچه کنید؛ این فایل‌ها برای جایگزینی کورکورانه کامل `src/main.js` طراحی نشده‌اند.
6. پیش از استفاده عملیاتی، تست‌های authorization، ذخیره تنظیمات scoped، نشست کاربران و حفظ داده‌های workspace را اجرا کنید.

## محدودیت‌های ماکت

- هیچ عملیات واقعی روی پنل اعلام حریق انجام نمی‌شود.
- ورود و احراز هویت واقعی در این بسته پیاده‌سازی نشده است.
- دکمه‌های پنل و تنظیمات نمایش بخش‌های UI هستند؛ عملیات دستگاهی واقعی ندارند.
- داده‌های فعالیت صرفاً برای نمایش layout هستند.
- در محیط عملیاتی، permissionها و data filtering باید در سرور اعمال شوند؛ این فایل فقط رابط کاربری را نمونه‌سازی می‌کند.
